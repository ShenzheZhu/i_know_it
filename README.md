# I Know It!

Enhance Chrome screenshots while keeping other screenshots and copies unchanged. A Chrome extension and a small macOS companion prepare the original image and a Markdown context file for pasting into Codex desktop. Click the extension's toolbar button to open a small panel with an **ON / OFF** switch. The choice survives browser restarts.

This is an experimental macOS implementation. Chrome transport and clipboard behavior are tested. Real macOS region captures have also been verified through image and Markdown attachments supplied by the user in Codex desktop, including a fresh capture with webpage CSS coordinates. Other agent platforms, including Claude Code terminals, are not yet supported.

## Install

Requires macOS and Google Chrome. A precompiled package supports only the architecture and minimum macOS version recorded in its `native/prebuilt/build.json`. A source ZIP is not a precompiled installer. Developer ID signing and notarization of a public installation package are still pending.

1. **Precompiled package:** extract it to a permanent folder, then double-click **Install.command**. Terminal opens for setup and shows the result. No compiler, signing key, or typed command is required. **Source checkout:** list valid identities with `security find-identity -v -p codesigning`, then run `IKI_SIGNING_IDENTITY=YOUR_CERTIFICATE_SHA1 ./install.sh` using the exact 40-character fingerprint. Source builds require Apple's Command Line Tools; set `IKI_SIGNING_KEYCHAIN` only if the identity is in a specific keychain. Subsequent source installs remember these public signing settings. If no valid identity is available, installation stops without replacing the helper; it does not create or trust a certificate automatically.
2. Open `chrome://extensions`, enable **Developer mode**, and **Load unpacked** this folder.
3. Pin **I Know It!** to the toolbar so its switch is always accessible.
4. To enable Chrome screenshot context with your macOS **Copy picture of selected area to the clipboard** shortcut, click **Allow region context** in the switch panel, then allow **Input Monitoring** in macOS settings. If no system dialog appears, open **System Settings > Privacy & Security > Input Monitoring** manually. The panel shows this path after a request and reports a failed connection explicitly. The default shortcut is **Control + Shift + Command + 4**; customized bindings are read from System Settings. This is an initial setup action, separate from taking screenshots. macOS determines whether permission is attributed to Chrome or its native companion; use the entry shown by the system. When you return to Chrome after opening the permission settings, the extension reconnects its companion once to refresh cached permission state. Follow any restart instruction from macOS if the panel still reports unavailable.

Packaged installs verify the binary and source hashes, declared platform compatibility, and actual signature before copying the helper. Updates must keep the installed certificate and default designated requirement. Invalid or incomplete packages stop without compiling a replacement. A transition from a local development certificate to Developer ID requires a deliberate migration; this installer does not rotate the identity or change macOS security settings. Download packages only from the trusted project release: a matching hash and a certificate named in the same package do not independently authenticate its publisher.

`IKI_SIGNING_KEYCHAIN` restricts identity lookup. The certificate chain must still be resolvable through the user's normal keychain search list ([Apple's trust API notes](https://github.com/apple-oss-distributions/Security/blob/main/trust/headers/SecTrust.h#L695)). Signing also requires the keychain containing the private key to be unlocked. The installer does not change certificate trust or the keychain search list.

Version 0.6.8 restricts enrichment to matched Chrome selections. It also settles its own previous clipboard restoration before observing the next shortcut, preventing that internal write from invalidating a new selection. Input Monitoring and a timely Chrome window observation are required; images without this evidence pass through unchanged. Migrating an older ad hoc installation to a signed identity may require authorization once. The extension also initializes its collector in already-open HTTP(S) pages when their current receiver is missing, then synchronizes the switch state. Healthy receivers are reused; restricted and closed pages retain the available basic observations.

Version 0.6.9 also settles an earlier external clipboard change before starting a new Chrome selection. Previously, a screenshot outside Chrome could reach the clipboard just before the next Chrome shortcut, and the next polling tick could mistake that older image for the new selection and cancel its context. A private-pasteboard regression reproduces this ordering and verifies recovery without OFF/ON. Two real Finder → Chrome → Codex sequences passed without toggling or restarting the companion; the final user message preserved both attachments and fresh geometry. Acceptance is recorded in [issue #15](https://github.com/ShenzheZhu/i_know_it/issues/15).

The public manifest key keeps the extension ID stable. The installer registers a local Native Messaging executable for Chrome and Chrome for Testing. Chrome starts it when the extension connects and stops it when the connection closes. There is no server, MCP, account, API key, telemetry, or network upload.

The installer signs builds with the stable identifier `com.iknowit.bridge` and the selected certificate. It uses the default designated requirement generated by `codesign`; it never writes a custom requirement. Updates must satisfy the previous signed version's requirement and retain its exact certificate identity. A missing key, signing failure, or identity mismatch stops the update before the helper or registrations are replaced. Certificate rotation requires a deliberate migration and is not automatic.

The local receipt records the final signed executable hash, certificate fingerprint, default requirement, source hash, architecture, and compiler details. Matching signed installations are verified and reused with their bytes and modification time preserved. Old ad hoc receipts cannot take this reuse path. A signed helper without signing fields in its receipt is checked before rebuilding, so missing receipt fields cannot silently change its signer. Uninstalling does not delete your signing identity. The installer neither changes system trust nor grants Input Monitoring. [Apple explains why ad hoc identities change across builds and how default requirements identify updates](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements). Live permission continuity still needs separate verification; successful signing alone is not screenshot acceptance.

## Use

Use your existing macOS selected-region-to-clipboard shortcut over Chrome, then paste as usual into Codex desktop. There is no new screenshot shortcut, selection overlay, preview page, toast, notification, or image annotation. The switch panel appears only when you click the extension icon; taking a screenshot and pasting remain silent.

With the switch **ON**, a matching Chrome region screenshot is prepared as two local file attachments while Codex is foreground: `screenshot.png` and `context.md`. Codex's inspected paste handler accepts an image and a nonempty Markdown file together; the Markdown is a file attachment/context reference, not inline text. A user-supplied Codex desktop message confirmed receipt of both files with matching image bytes and region metadata on September 8, 2026. Automated control of the native composer remains unavailable.

With the switch **OFF**, the companion stops handling images and restores any clipboard content it currently owns. Moving to another app also restores the original clipboard representations. The companion checks clipboard ownership before updating or restoring it; macOS does not provide an atomic compare-and-write operation. Other-app screenshots, ordinary copied images, copied image files, text and multiple-file copies pass through unchanged. A later switch to Chrome or Codex cannot make an unrelated copy eligible.

## What the context means

The Markdown contains the image's pixel dimensions and clipboard observation time, plus the Chrome app, URL, title, tab/window IDs and window bounds observed at the screenshot shortcut. Acceptance requires a matching region gesture begun in a supported Chrome browser and a selection contained within its recorded, focused window bounds, allowing one display point for rounding. The app active when delayed image bytes arrive or when pasting cannot substitute for that screenshot-time evidence. These basic observations remain available for Chrome internal pages such as `chrome://extensions/`, without injecting a script. Viewport, scroll position, and device pixel ratio require a readable web page; browser zoom is included when available. Missing page measurements are stated separately instead of discarding readable tab information. Window mode is recorded separately: **Browser window state** is Chrome's normal/minimized/maximized/fullscreen state; **Browser window fullscreen** derives from that state; **Document element fullscreen** means an element entered the web Fullscreen API. Maximizing a window is not fullscreen. Missing or invalid states are unknown, including document state on unreadable pages. The extension does not infer fullscreen from window dimensions.

With Input Monitoring allowed, the companion passively observes the system's configured region-to-clipboard shortcut and a plain region drag. It reads that binding at startup and checks for changes once per second; changing or disabling it cancels any pending selection. Invalid bindings and unmodified printable-key bindings leave the clipboard unchanged. It does not replace the shortcut, post input, take its own screenshots, or store keyboard text/history. A single new clipboard image within two seconds of mouse-up must match the observed drag dimensions within `2 × display backing scale` pixels per axis. This allows one logical point per edge as a heuristic rounding tolerance; it is not a universal macOS rounding rule. The context preserves the raw pointer extent in global display points and display-relative backing pixels, which may be fractional, plus the display's bounds and scale. These are not exact image crop coordinates. Negative secondary-display origins are retained. Full-display coordinates therefore do not depend on stretching the cropped image to a standard aspect ratio.

The foreground app is recorded at the shortcut. Browser context is requested then and retained only if received within one second and before mouse-up. Replies arriving after selection are discarded so a later tab cannot be backfilled as screenshot context. Missing or late shortcut-time browser context leaves the clipboard unchanged. There is no post-copy browser-context fallback for unrelated images.

On readable HTTP(S) pages, an experimental estimate can also express the raw drag in viewport and top-document CSS pixels. It uses one trusted mouse screen/client calibration together with browser zoom to estimate the content viewport's screen origin. Version 0.6.4 retains that single observation while measured geometry stays unchanged, including when the pointer pauses for more than one second. Its original timestamp and actual age are preserved; it is not relabeled as a fresh observation. Pure top-document scrolling preserves the original calibration when viewport-origin geometry is unchanged, while updating document coordinates from the current scroll position. Scroll still invalidates a screenshot selection already in progress. Resize, navigation, visual-viewport, fullscreen, and pointer-lock signals clear calibration, including structural signals whose measured dimensions are unchanged. Hidden, frozen, or disabled pages also discard it. The page keeps no pointer history. An estimate requires agreement between page and browser window measurements, display scale, and unchanged geometry, with the content bounds on the captured display and the drag inside them. Pointer mapping also works in browser fullscreen when the same checks pass. When no calibration is supplied, a separate fullscreen estimate is available only if Chrome and page-reported window bounds agree and both scaled viewport dimensions match those bounds within one display point. It uses their visible overlap, requires current enabled/visible/focused state and a shortcut-correlated browser timestamp, and does not fabricate a pointer observation. A malformed or inconsistent supplied calibration cannot silently choose this fallback. Smaller viewports, such as space reserved for sidebars or docked developer tools, still require a valid pointer calibration. Inconsistent timestamps, pinch zoom, document-element fullscreen and ambiguous geometry leave CSS coordinates unknown. Browser-chrome changes that shift the content origin without observable geometry changes remain an estimation risk. The Markdown includes the calibration and page-window measurements to help diagnose rejected estimates. This happens passively and adds no screenshot step. On macOS Chrome, nine pointer/DOM samples paired with independent native accessibility bounds and seven additional edge samples passed conversion checks within one CSS pixel, across 80%, 90%, 100%, 110%, 125%, and 150% zoom and a scrolled page. This reproduced and fixed Float32 pointer rounding at display boundaries; only 0.001 display point of edge tolerance is allowed. A fresh manual screenshot-to-Codex handoff on version 0.6.0 included the original image and complete CSS metadata; the received PNG matched the stored image byte for byte. A separate delayed paste reproduced loss of coordinates when Universal Clipboard restored an earlier local generation ([issue #5](https://github.com/ShenzheZhu/i_know_it/issues/5)). Version 0.6.1 retains one displaced, correlated screenshot in memory for up to ten minutes. Recovery requires the exact earlier clipboard generation, every advertised representation to match, and the same pasteboard service process and start time. Copying an identical image as a new generation does not reuse old coordinates. Missing or changed evidence leaves coordinates unknown; OFF discards the suspended state. Mutable file-URL inputs are excluded from this recovery. The captured generation rollback is covered by automated private-pasteboard tests; a live Universal Clipboard expiry has not yet been repeated on a fixed version.

Version 0.6.5 preserves a valid calibration when the extension repeats the same ON state. The saved context also records the current calibration status and visibility/focus state, so a missing estimate can distinguish an unfocused pointer from a hidden page, structural change, or invalid timing. It retains no event history or rejected coordinates. A live 0.6.4 paused-pointer check still lost calibration; the repeated-ON reset is independently reproduced, but is not yet established as the cause of that receipt. A native Codex receipt on version 0.6.5 retained the original calibration for 5.56 seconds, preserved the original PNG, and matched the known page fixture within one image pixel; a subsequent page scroll preserved its saved metadata. This confirms that fixture scenario, without establishing the exact cause of the preceding failure.

These are **observations, not verified screenshot provenance**. macOS does not supply a capture receipt in an ordinary clipboard image. Time and size can correlate an observed drag with an image, but an unrelated same-size copy can still collide. Selections outside the recorded Chrome window are rejected, but these bounds cannot identify an overlapping window inside that rectangle. The actual source app/page and crop origin therefore remain unverified; agents must not treat the observed rectangle, browser window bounds, or CSS estimate as a verified click target. CSS estimates describe the raw drag, not an exact image crop or iframe-local coordinates.

Full-screen and region images retain their size; they are not stretched to a standard screen ratio. Existing PNG bytes are preserved. Single-frame TIFF images with normal orientation are encoded as PNG without resizing. Other image formats and rotated TIFF files pass through unchanged. Geometry invalidations received while selection is pending, including the gap between mouse-up and the matching clipboard image, leave CSS coordinates unknown. Once the matching image is accepted, version 0.6.2 preserves that capture-time snapshot: later browser changes do not erase its recorded coordinates. These values describe the screenshot-time observations; agents must inspect the live screen before clicking.

Version 0.6.2 fixes a second reproduced handoff defect: a valid prepared CSS estimate was erased after a later browser geometry notification. Completed capture metadata now stays unchanged across those notifications, including when Universal Clipboard temporarily displaces it. The native checks cover six timing boundaries around selection, image acceptance, and file creation, plus 20 clipboard rollback scenarios. The existing warning to re-observe the live page remains. Notifications do not provide an authoritative capture receipt or occurrence timestamp; freezing the accepted snapshot does not turn correlation into verified provenance.

Version 0.6.3 received a 904 × 456 PNG byte for byte with the correct test-page URL and raw screen region, but CSS coordinates were unavailable. Scrolling afterward did not change the stored files. That receipt did not record which mapping prerequisite failed. Separately, the former one-second calibration cutoff was reproduced in a native regression probe and removed in 0.6.4; that probe alone did not establish live acceptance.

## Current limits

- Region monitoring is experimental. A real macOS Control + 4 test reproduced missing region metadata on version 0.5.2: the image and context file were preserved, but the companion expected the default shortcut. Version 0.5.3 reads the configured shortcut; a subsequent real capture and user-supplied Codex attachment pair verified matching raw drag coordinates, display scale, image dimensions, and preserved PNG bytes. The panel's monitoring status indicates that an event tap was established, not that a screenshot was successfully attributed.
- Only plain, single-display region selection is correlated. Space/window mode, moving a selection, extra Shift/Option/Command modifiers during a drag, cancellation, lost events, changing display geometry, cross-display or mirrored-display regions, mismatched sizes, multiple clipboard changes, and timeouts leave the clipboard unchanged. Releasing the original shortcut keys before dragging is supported. Whole-display and window-mode screenshots pass through unchanged. Chrome itself may be in fullscreen mode when taking a supported region screenshot.
- The companion requests Input Monitoring only after the permission button is clicked. Turning the switch OFF stops input monitoring and discards pending selection state. No Screen Recording or Accessibility permission is requested by this feature. The installer now requires stable signing; an older ad hoc installation needs a one-time signed migration. Signature validation does not grant permissions, and actual Input Monitoring continuity across updates remains unverified.
- A 50 ms clipboard check and app-activation event keep the process passive. An immediate paste before detection can contain only the original image. Late browser responses cannot add context to an unverified capture or rewrite its source.
- Chrome must remain running. One Chrome profile owns the companion at a time; use the toolbar switch in that profile. Multiple simultaneous Chrome profiles are not supported.
- Incognito, unsupported URL schemes, and uncertain page/focus transitions do not receive tab attribution. Chrome internal pages and web pages that deny script access can still provide basic tab/window observations after revalidation, but no page measurements. DOM content and cross-origin iframe contents are not collected.
- Images above 100 MB, 64 million pixels, or 32,768 pixels on either axis, animated images, concealed/transient clipboard items, and multiple clipboard items pass through unchanged. This may exclude exceptionally large multi-monitor captures.
- Disk failures preserve ordinary paste. Normal disconnect and termination restore owned content. A forced kill or process crash can leave the two generated file references on the clipboard; copying again replaces them.
- macOS spaces, physical monitor switching, third-party screenshot tools, and broader native Codex composer flows remain unverified beyond the received image/context cases described here. Windows, Linux, remote agents, and Claude Code are not supported by this companion.

Claude Code CLI 2.1.190 does not support this zero-step image-plus-Markdown handoff. Its [documented image-paste shortcut](https://code.claude.com/docs/en/interactive-mode#general-controls) imports an image. Inspection and isolated tests of the installed handler show that it then returns before reading clipboard text; another clipboard representation does not attach the context. A [UserPromptSubmit hook](https://code.claude.com/docs/en/hooks#userpromptsubmit) can add text context, but its input does not identify the current image attachments. Source inspection also found that this version runs the hook before the current message reaches the transcript. The companion does not install a hook that guesses from the latest screenshot or alter ordinary terminal pastes.

Saved images and context stay locally under `~/Library/Application Support/I Know It/captures/`, with private file permissions. They remain until deleted so agent references keep working. Page URLs and titles may contain sensitive information. Disabling the switch stops enrichment; it does not delete prior captures.

Run `./uninstall.sh`, then disable or remove the extension, to remove the companion. Saved captures are retained.

## Checks

```sh
node check.cjs
xcrun swiftc native/main.swift -o /tmp/i-know-it-check
/tmp/i-know-it-check --self-test
```

The extension check covers correlated context, zoom and negative window coordinates, focus/tab races, restricted pages, persisted switches, rapid setting changes, and disabled restarts. The native check uses an isolated named pasteboard to exercise original-image preservation, destination changes, toggle restoration, rejected late context, and newer-copy ownership. It does not touch the system clipboard.

With Playwright and its Chromium browser available, run `node check-popup.cjs` to check the switch panel. It loads the actual popup HTML and background JavaScript in an isolated local fixture and covers clicking, keyboard control, saved state, interrupted replies, and light/dark themes. It also simulates popup sizing feedback from initial widths of 25, 181, 280, and 320 CSS pixels at device pixel ratios 1 and 2, checking the resulting width, switch containment, and click-target alignment. This check does not install the extension, touch the system clipboard, or establish native Codex composer acceptance.

The historical `check-browser.cjs` copied-file fixture predates the Chrome-only policy and is no longer a supported acceptance command.

The September 7, 2026 run on macOS 26.6.2 / Chrome for Testing 151.0.7922.34 verified a real native-host context request and an ordinary paste containing both PNG and Markdown with identical bytes. This does not establish native Codex composer acceptance.

For an automated artifact check using Codex CLI, run `node check-agent.cjs` with Playwright and an authenticated `codex` command available. Set `CODEX_BINARY` if the CLI is installed elsewhere. This calls Codex with a generated test image, so normal account usage applies. The check compiles the real native clipboard engine with a private-pasteboard fixture, verifies byte preservation and Retina dimensions, and asks Codex to read a random visual code and the generated Markdown. It never opens Codex desktop or changes the system clipboard.

On September 8, 2026, this check passed: Codex CLI read the image code, observed URL, 1200 × 800 dimensions, and unknown crop origin correctly. Additional regression checks found and fixed stale screenshots being reapplied after clipboard ownership loss and old replies reaching a replacement native connection. Extension invalidation also now leaves passive page handlers silent. Malformed input, message-size limits, late replies, disabling, and reconnect checks pass. Automated native Codex desktop control is blocked by the available tool policy; this CLI result alone does not prove the desktop paste flow. The later user-assisted capture result below provides separate evidence.

CI also runs `check-context-browser.cjs` in a temporary Chromium profile with an inert native port. It verifies that production background code reads the isolated content script, that page code cannot replace its getter or forge a trusted pointer event, and that toggles, navigation, scroll, and resize clear stale anchors. It does not access the installed companion or a desktop chat.

The extended checks can be run without accessing Codex desktop or the everyday Chrome profile:

```sh
node check-process.cjs
node check-images.cjs
node check-install.cjs
```

Installer checks use real Swift compilation and, by default, an explicitly synthetic `codesign` protocol fixture. They exercise migration, signing failures, identity and requirement mismatches, unchanged reuse, and rollback; they do not prove cryptographic identity continuity or macOS permission retention. To run the signing checks with a real existing identity, use `IKI_TEST_SIGNING_IDENTITY=YOUR_CERTIFICATE_SHA1 node check-install.cjs`, optionally setting `IKI_TEST_SIGNING_KEYCHAIN`. This mode does not create certificates or change keychain trust. Both modes redirect installation files to temporary directories and leave the installed helper alone.

`check-process.cjs` runs the native executable with only its pasteboard, app observation, and support directory redirected to fixtures. It simulates matched Chrome gestures inside the temporary harness, without OS input, and checks split pipe messages, EOF, SIGTERM, SIGINT, malformed input, OFF, a newer copy during shutdown, a broken output pipe, and a competing host. Negative cases preserve non-Chrome and ordinary copies, missing or late context, copied files, and selections outside the observed Chrome window. Every image write includes a 200 ms gap after clearing the pasteboard, covering screenshot tools that supply image data later without another change count. A separate case advertises PNG before supplying bytes at the same generation; version 0.6.1 retries this missing-data state for at most two seconds. `check-images.cjs` checks byte preservation and metadata for nine sizes from 1 × 1 to 7680 × 4320, plus rejection of a valid image above the 64-million-pixel limit. `check-install.cjs` runs real Swift compilation and registration commands inside a temporary Application Support tree, covering reinstallation, validation, permissions, failures, foreign files, symlinks, and uninstall retention.

Version 0.6.1 also includes 21 private-pasteboard recovery cases covering generation rollback, raw images and prepared attachment pairs, unavailable data, changed service identity or contents, privacy markers, expiration, OFF, and invalidated geometry. These replay the observed generation sequence through the production state machine without controlling Universal Clipboard.

The native self-test also covers 4,096 deterministic state transitions (seed `0x494B49`). This reproduced and fixed an older image being reapplied after a duplicate enable message. Extension checks cover fractional zoom/viewport offsets, closed or navigating tabs, changing incognito flags, and storage failures. If Chrome cannot read saved settings, the extension starts OFF; a storage write failure does not disable the live switch, but persistence remains unavailable until a later write succeeds.

Version 0.5.0 adds 88 deterministic region checks for the standard shortcut, released modifiers, reverse drags, negative display origins, Retina dimensions, timeouts, clipboard generations, display changes, and cancellation. Private-pasteboard integration checks verify selection metadata, preserved image bytes, rejection of post-selection browser replies, and OFF restoration. Permission checks use injected denials and never open a real event tap. Popup checks exercise explicit permission requests and all 16 layout combinations with the permission copy visible; forged callers, old ports, startup, ON, and ordinary panel opening cannot request permission.

Version 0.5.1 fixes a reproduced permission lifecycle problem on macOS 26.6.2: the system granted Input Monitoring, but the existing companion retained its earlier denied state. Gracefully reconnecting the same executable established an enabled listen-only event tap. The extension now performs that reconnect once after an explicit permission request and a return from another app. Ordinary focus changes do not reconnect it. The native executable is unchanged from 0.5.0; existing installations only need the updated extension files, preserving the companion's granted code identity. This verifies permission recovery, not the geometry or paste result of a real system screenshot.

Version 0.5.2 accepts finite fractional mouse positions, including intermediate drag events that previously cancelled otherwise valid selections. Its 147 deterministic region checks cover fractional endpoints, reverse drags, negative origins, Retina scaling, bounded dimension differences, and nonfinite input. Metadata preserves raw coordinates and identifies the size tolerance; missing coordinates include the last tracking status, which may predate the image. This version changes the native companion and requires rerunning `install.sh`; updating extension files alone does not load the fix. macOS may require Input Monitoring to be granted again for the rebuilt executable.

Version 0.5.3 follows the configured macOS region-to-clipboard shortcut, including a different physical key or modifiers. Disabled or malformed settings do not fall back to an active shortcut, and changing a binding cancels pending selection context. The user supplied both the image and Markdown in Codex desktop; the PNG matched the driver capture and stored file byte for byte. ## Prepare a precompiled package

This is a publisher command, not a recipient setup step. With Node.js and Apple's Command Line Tools available, run it from a clean, committed checkout:

```sh
node package.cjs /path/to/i-know-it-host /path/to/install-receipt.json /path/to/output.zip
```

The packager verifies an existing signed helper against its receipt and this checkout's native source, reads its actual architecture and minimum macOS target, and adds those bytes to the committed source archive. It copies only public build fields into `native/prebuilt/build.json`; local installation paths and keychain settings are excluded. It neither compiles nor signs the helper. An existing output file is not overwritten.

Run `node check-package.cjs /path/to/i-know-it-host /path/to/install-receipt.json` to check packaging with a real existing signature in a disposable source checkout. It verifies archive contents, permissions and rejection paths without installing, signing, or accessing private keys. `node check-install.cjs` also covers precompiled installation with the compiler disabled, update identity checks, package corruption, and rollback. Its default signing protocol remains synthetic; neither command establishes notarization or a first-open Gatekeeper result.

A local development certificate does not establish a trusted public publisher. Public distribution still needs Developer ID signing, hardened runtime, notarization, and a downloaded-package first-open check; packaging alone supplies none of these. The currently accepted local helper targets Apple silicon and macOS 26.0 or later. Testing source builds on older CI runners does not make that binary compatible with older systems. [Apple's distribution guidance](https://developer.apple.com/developer-id/) describes the signing and notarization requirements.
